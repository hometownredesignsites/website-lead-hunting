# Contact information in candidate CSVs

The site audit collects publicly displayed contact values from the homepage and, when needed, up to two linked same-site Contact/About/Team pages. It reads email addresses from page text, `mailto:` links, and structured data; phone numbers come from page text, `tel:` links, and structured data. It looks for a named person only when a public page explicitly connects that name to a role such as owner, founder, president, or contact, or when structured Person data provides a relevant job title or relationship. The exported value combines name and title, for example `John Doe, Owner`. It records the source page and confidence in the private candidate ledger. It does not submit forms or guess missing names.

The CSV exports use `location` for the city and full state name, such as `Westminster, Colorado`. Contact columns are `email`, `phone`, `contact_name`, `contact_status`, and `ContactSource`. `contact_name` contains the public name and role (for example, `John Doe, Owner`) when explicit evidence is found. `contact_status` continues to describe the email/phone lookup; a name can be present while that status is `not_found`. `ContactSource` is the exact page URL where the selected email was found; it remains blank when no email was found. The contact-name source and confidence, and phone source, remain in the private candidate ledger. High/medium exports include a scalar `PreviewURL` column, blank until a portfolio is deployed. The visual scoring ledger reads contact values from the private source run ledger and stores them in `scores/SCORING_MASTER.csv` and `scores/HIGH_MEDIUM_CANDIDATES.csv`. The high/medium file is refreshed as valid visual replicates arrive and includes only current Medium and High outcomes. Blank contact fields mean the bounded lookup did not find a value; they do not establish that a business has no contact details.

The unredacted run ledger and CSV are committed to the private provider branch first. Before the public repository receives its temporary Actions artifact, a redaction step blanks raw email, phone, and contact-name values in the artifact copy while preserving contact status, provider-domain classification, and email source page URLs. Screenshots can still visibly show public contact details. Actions logs and artifacts belong to the public workflow repository and expire according to its artifact retention policy; they are not part of the private repository.

The extraction is a bounded automated aid, not contact verification. It can miss values rendered only after interaction, hidden in images, encoded unusually, or outside the inspected pages. Confirm the source page before outreach.
